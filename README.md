# Ultimate Neural Network Visualizer

Interactive MNIST handwritten-digit classifier with a real-time neural network visualization dashboard. Users draw on a 28×28 canvas, and the app displays live neuron activations, weighted connections, confidence distributions, backpropagation gradients, and an optional 3D network scene — all updated in real time via WebSocket.

## Purpose

The project exists to demonstrate how a feedforward neural network classifies handwritten digits (0–9) from the MNIST dataset. It is intended for educators, students, and developers who want to visually inspect the internal state of a trained network — neuron activations, weight strengths, gradient flows, and prediction sensitivity — without writing any code.

## Features

- **28×28 drawing canvas** with configurable brush radius and strength; pointer interpolation for smooth strokes
- **Real-time inference** via Socket.IO — draw and analyze without page refreshes
- **2D SVG network graph** showing all four layers (784 → 96 → 48 → 10) with neuron activation colors and sampled connection webs
- **Dynamic edge highlighting** — strongest signal paths between layers are overlaid on the graph
- **Confidence distribution** bar chart (0–9 digits) with animated fill
- **Layer statistics** panel (mean, max, sparsity per layer)
- **Output weight heatmap** (Hidden₂ → Output matrix, 48×10) with color-coded positive/negative weights
- **Top contributor** list — which hidden-2 neurons most influence the predicted digit
- **Backpropagation metrics** — loss, target digit, per-layer gradient norms, and strongest weight-update candidates
- **Adjustable controls**: per-layer weight scaling (0.45×–1.75×), per-digit output bias offsets (−2 to +2), and forced target digit for gradient computation
- **Live training** — apply a single labeled backpropagation step (fine-tune on user input)
- **3D network scene** (Three.js via React Three Fiber) with auto-rotate and orbit controls; lazy-loaded
- **3D pipeline visualization** — animated step-by-step walkthrough (input matrix → weight computation → hidden layers → prediction)
- **Automated showcase mode** — draws a random digit, animates edge reveal layer-by-layer, scrolls through sections, and runs the pipeline
- **Prediction history** with per-entry confidence mini-bars; persisted to MongoDB Atlas when available, with automatic in-memory fallback
- **Model improvement script** (`improve_model.py`) with checkpoint rotation and metadata tracking
- **Docker Compose** deployment (ml-service + web service)

## Architecture

### High-Level Design

The application is split into three processes that communicate over HTTP:

1. **Python FastAPI service** (port 8000) — owns the PyTorch model, runs forward/backward passes, returns structured JSON.
2. **Node.js Express + Socket.IO bridge** (port 4000) — serves the built frontend static files, proxies ML requests, broadcasts real-time events, and persists history to MongoDB.
3. **React frontend** (Vite dev server or built files) — provides the user interface, connects to Socket.IO for real-time updates.

In production (Docker Compose), the Vite dev server is replaced by the built static files served directly by Express.

### Request Flow (Analysis)

```
User draws on canvas → [DigitCanvas] → grid (28×28 float array)
    → [App.jsx] calls socket.emit("analyze-digit", {pixels, adjustments, includeBackprop})
    → [server.js] socket handler receives event
    → HTTP POST /analyze → [ml_server.py] → [model_utils.analyze_digit]
    → structured JSON returned
    → [server.js] appends to history, broadcasts "prediction-history" and "analysis-complete"
    → [App.jsx] receives events, updates state
    → [NetworkGraph, ActivationCharts, PredictionHistory] re-render with deferred value
```

### Response Flow

The FastAPI `/analyze` endpoint returns a JSON object with these top-level keys:

- `prediction` — `{digit, confidence, probabilities[]}`
- `layers[4]` — per-layer `{name, size, activations[], stats, sparsity, topNeurons[], grid, gradientGrid, preActivations, logits}`
- `dynamicEdges` — `{input_to_hidden_1[], hidden_1_to_hidden_2[], hidden_2_to_output[]}` each containing `{from, to, signal, magnitude, activation, weight}`
- `topContributors[10]` — `{index, contribution, activation, weight}`
- `controls` — `{layerScales[], outputBiasOffsets[], targetDigit}`
- `backprop` — `{loss, targetDigit, layerGradientNorms[], strongestWeightUpdates{}}`
- `weightStats` — per-layer `{min, max, mean, std}`

### State Management

- **React state** lives entirely in `App.jsx` using `useState`, `useDeferredValue`, and `useTransition`. No external state library.
- The `analysis` object is wrapped in `useDeferredValue` so the UI never blocks during re-render.
- **Socket.IO** acts as the real-time data bus: the server broadcasts `prediction-history` to all connected clients after every analysis or training step.
- **MongoDB** (optional) persists history entries; on startup, the server loads the most recent `MAX_HISTORY` entries into an in-memory array.

### AI Workflow

The `VisualizerNet` is a three-layer feedforward network:

```
Input (784) → Linear(784→96) → Dropout(0.25) → ReLU → Linear(96→48) → Dropout(0.25) → ReLU → Linear(48→10)
```

Training (`train_model`): 6 epochs, batch size 128, Adam (lr=0.001, weight_decay=1e-4), StepLR scheduler (step=3, gamma=0.5), CrossEntropyLoss, best checkpoint saved.

Improvement (`improve_model`): fine-tunes from the best saved weights, rotates previous best to a `.pth.bak` file, and writes metadata to `model_checkpoints.json`.

Inference (`analyze_digit`): clones weights to apply layer scaling, performs forward pass with optional backpropagation, extracts per-layer activations, gradients, top connections, and top-K contributing hidden neurons.

### Storage Flow

```
Prediction entry created → appended to in-memory array (max MAX_HISTORY)
    → persistHistoryEntry() called asynchronously
    → upserts into MongoDB collection `predictionHistory`
    → deletes stale entries beyond MAX_HISTORY
    → if MongoDB unavailable, entry stays in memory only
```

### Error Handling

- **Server failures**: Express catches errors from Axios calls to FastAPI and returns 502 with normalized error JSON.
- **MongoDB failures**: `connectToDatabase` returns `null` silently; `persistHistoryEntry` and `loadHistoryFromDatabase` both handle null collection gracefully. The `databaseState` object tracks connection status and is exposed via `/api/health`.
- **Frontend errors**: displayed in a red animated error banner at the bottom of the controls panel. Socket events wrap errors in `{ok: false, error}` and reject the acknowledgement promise.
- **Model compatibility**: `_state_dict_compatible` validates that saved weights match the current architecture; incompatible weights trigger automatic retraining.

## Database

**Type**: MongoDB Atlas (optional, with automatic in-memory fallback).

**Database**: `NumberPredictor` (configurable via `MONGODB_DB_NAME`).

**Collection**: `predictionHistory` (configurable via `MONGODB_COLLECTION`).

**Document schema**:
```json
{
  "id": "string (timestamp-random)",
  "createdAt": "ISO 8601 string",
  "digit": "number (0-9)",
  "confidence": "number (0-1)",
  "probabilities": [10 numbers],
  "controls": {
    "layerScales": [3 numbers],
    "outputBiasOffsets": [10 numbers],
    "targetDigit": "number"
  }
}
```

**Indexes** (created on connection):
- `{ createdAt: -1 }` — for sorted retrieval
- `{ id: 1 }` — unique, for upsert

**Data lifecycle**: The database stores at most `MAX_HISTORY` entries. When a new entry is upserted, stale entries beyond the limit are deleted. On startup, the server loads the most recent entries into memory.

## How It Works

1. **The user opens the app** — the frontend (React) connects to the Express server via Socket.IO and fetches the current model weights and prediction history via HTTP.
2. **The user draws a digit** — the `DigitCanvas` renders a 28×28 interactive grid. Each cell holds a float (0.0–1.0) representing pixel intensity.
3. **The user clicks "Analyze"** — the 784 pixel values plus control parameters (layer scales, bias offsets, target digit) are sent via a Socket.IO `analyze-digit` event.
4. **The Express server receives the event** — it forwards the payload as an HTTP POST to the FastAPI Python service at `/analyze`.
5. **FastAPI runs inference** — `model_utils.analyze_digit` loads the cached PyTorch `VisualizerNet`, optionally applies layer scaling and bias offsets to cloned weight tensors, performs a forward pass (Linear → ReLU → Linear → ReLU → Linear → Softmax), and optionally computes gradients via a backward pass.
6. **The analysis JSON is returned** — contains the predicted digit, per-class probabilities, per-layer activations and statistics, the strongest signal-carrying connections between layers, top-K contributing hidden neurons, backpropagation metrics, and weight statistics.
7. **The Express server broadcasts the result** — it emits `analysis-complete` to the requesting socket and `prediction-history` to all connected clients. It also asynchronously upserts the entry into MongoDB.
8. **The frontend re-renders** — `App.jsx` updates its `analysis` state (through `useTransition` and `useDeferredValue`). The `NetworkGraph` highlights active neurons and edges. `ActivationCharts` animates confidence bars and shows the weight heatmap. `PredictionHistory` prepends the new entry with an animated mini-bar chart.
9. **The user can adjust controls** — changing layer scales or bias offsets re-weights the cloned tensors on the next analysis, allowing sensitivity inspection without retraining.
10. **The user can run a training step** — clicking "Apply step" sends a `train-digit` event with a label. FastAPI runs one optimization step (Adam, lr=0.0005), saves the updated weights to disk, and returns the analysis of the updated model.
